- AC-1.1 [rule] prd.md:45 "WHEN POST /items receives {"name": "Coffee beans", "price": 8.5, "quantity": 2} THE SYSTEM SHALL respond 201 with {"id": "<id>", "name": "Coffee beans", "price": 8.5, "quantity": 2} and store the item"
- AC-1.2 [rule] prd.md:46 "WHEN two items are added THE SYSTEM SHALL give them different ids, even when name, price and quantity are identical, and keep both items"
- AC-1.3 [rule, proposed] prd.md:47 "WHEN name is missing, not a string, empty, or only whitespace THE SYSTEM SHALL respond 400 validation_error and store nothing"
- AC-1.4 [rule, proposed] prd.md:48 "WHEN price is missing, not a JSON number (a string such as "8.50" or a boolean counts as not a number), negative, or has more than 2 decimal places THE SYSTEM SHALL respond 400 validation_error and store nothing"
- AC-1.5 [rule, proposed] prd.md:49 "WHEN quantity is missing, not a JSON integer (8.0, "2" and true are rejected), or below 1 THE SYSTEM SHALL respond 400 validation_error and store nothing"
- AC-1.6 [rule, proposed] prd.md:50 "WHEN the body is not valid JSON or is not a JSON object THE SYSTEM SHALL respond 400 validation_error and store nothing"
- AC-1.7 [rule, proposed] prd.md:51 "WHEN the body contains a field other than name, price and quantity (including id) THE SYSTEM SHALL ignore that field and generate the id itself"
- AC-1.8 [rule] prd.md:52 "WHEN a request is rejected THE SYSTEM SHALL return a message that names the offending field"
- DR-1 [rule] prd.md:73 "An item has exactly four fields: id (string), name (string), price (number), quantity (integer)."
- DR-2 [rule, proposed] prd.md:74 "id is a UUID version 4 in canonical lowercase hyphenated form, generated by the server, unique within the process, and never reused."
- DR-3 [rule] prd.md:75 "name is stored exactly as sent apart from leading and trailing whitespace, which is trimmed; the trimmed value is non-empty."
- DR-4 [rule, proposed] prd.md:76 "price is held as decimal.Decimal with at most 2 decimal places, at least 0 (0 is allowed), and is returned in JSON as a number (8.5, not "8.50")."
- DR-5 [rule] prd.md:77 "quantity is an integer of at least 1, with no upper limit."
- NFR-1 [rule] prd.md:83 "NFR-1 | correctness | concurrent adds in the same process never lose an item or reuse an id | 100 concurrent adds leave exactly 100 items with 100 distinct ids | unit"
- NFR-2 [rule] prd.md:84 "NFR-2 | quality | lint and types are clean | 0 errors from ruff and mypy | CI command"
